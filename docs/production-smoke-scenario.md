# 本番動作確認シナリオ — 道場長ひとりで一巡する手順書

> - **作成日**: 2026-07-04
> - **目的**: 本番環境(`https://aiki-board.com`)で、道場長(オーナー)1 人がアカウント登録からボード運営・公開ページまでを実データで一巡し、動作を確認する。
> - **想定**: 蕨合気道会の道場長として実施。既存の AikiNote アカウントでログインする。
> - **使い方**: 上から順に実施し、各ステップの「期待結果」と実際の挙動を突き合わせる。ズレたらその場でスクリーンショット + 手順をメモして Claude に共有(→ 修正 PR)。スマホだけでも一巡できるが、PC + スマホの併用を推奨。

## 付録 A: プラン切り替え SQL(Supabase Dashboard → SQL Editor)

有料機能を本番で試すための一時措置(Stripe / 60 日トライアル実装までのつなぎ)。

```sql
-- ① 自分のボードと現在のプランを確認
select b.id as board_id, b.name, b.slug, p.code as plan, s.status
from aikiboard.boards b
join aikiboard.board_subscriptions s on s.board_id = b.id
join aikiboard.plans p on p.id = s.plan_id;

-- ② Standard に切り替え(<board_id> を①の値に置換)
update aikiboard.board_subscriptions
set plan_id = (select id from aikiboard.plans where code = 'standard')
where board_id = '<board_id>';

-- ③ Free に戻す場合
update aikiboard.board_subscriptions
set plan_id = (select id from aikiboard.plans where code = 'free')
where board_id = '<board_id>';
```

反映はアプリ側のリロードで即時(`hasFeature` は毎リクエスト DB を参照)。

## 付録 B: 1 人検証の既知の制約(不具合ではない)

- **自分の操作では通知が来ない**: 通知は actor(操作した本人)を除外して配るため、1 人だと通知ベルはほぼ空のまま。通知を見るには 7-3 の 2 人目アカウントで相互に操作する。
- **メールは送信されない見込み**: Resend のドメイン認証が未完了(0-3)。
- **OAuth ログイン・パスワード再設定の導線が無い**: メール/パスワードのみ(roadmap R1-3)。
- **アドミン任命・ボード削除・オーナー譲渡が無い**: roadmap R2-1〜R2-3 で実装予定。作ったテストボードを消したくなっても現状 UI からは消せない(必要なら SQL で削除するので声をかけてください)。
- **ヘッダーの検索(⌘K)・言語切替・アカウントボタンはダミー**: roadmap R4-2 / R4-3。
