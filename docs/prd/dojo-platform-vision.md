# dojo-platform-vision PRD

## 背景・目的

AikiBoardは、合気道の道場・会のコミュニティを運営する方のための道場管理＆コミュニケーションプラットフォーム。姉妹サービスである個人向け稽古日誌アプリAikiNoteと共通のアカウント基盤でつながり、個人の学びと道場のコミュニティが自然に行き来できる設計とする。

稽古スケジュールの共有、出欠の取りまとめ、道場メンバーに向けたお知らせ配信、メンバー同士の交流、会計の見える化、そして稽古の積み重ね(稽古内容や指導者の振り返り等)をアーカイブとして残すこと。道場運営に必要なことをひとつの場所にまとめる。

開発者(要望提出者)自身が、AikiNoteの開発・リリースで培った個人開発スキルを活かし、現在所属している道場や身近な合気道の組織・コミュニティで浮き彫りになっている課題を解決したいという動機で開発している。

## 対象ユーザー

- 道場や会・組織のオーナー(道場長・会長)
- その組織の幹部および事務局メンバー(アドミン)
- その組織に所属する一般メンバー(道場生)

## ユーザーストーリー

- オーナー・アドミンとして、稽古スケジュール管理や会員/道場生向けのお知らせ・メッセージ配信、月謝の支払い・出欠管理などの面倒な管理系タスクを、少しでもラクに済ませたい。
- オーナー・アドミンとして、道場/会・組織のちゃんとしたHPを持っておらず、集客〜宣伝やメンバー管理に苦労している。LINEやExcel等で無理やり済ませている作業を、もっと一元管理・効率化したい。

## 画面・API・データ

[Clarified: 2026-09-10 prd-refine] スコープ確定(ロール変更+ボード削除)に基づく輪郭:

- **ロール変更**: 画面は既存 `MembersView`(`specs/members/spec.md`)にロール変更UIを追加。API: `PATCH /api/members/:id/role`(新規、owner/admin実行可)。テーブル: `aikiboard.board_members`(既存`role`カラムを更新)。
- **ボード削除**: 画面は既存 `SettingsView`(`specs/settings/spec.md`)に削除UI(ボード名入力確認)を追加。API: `DELETE /api/boards/:id`(新規、owner限定)。テーブル: `aikiboard.boards`と関連テーブル(CASCADE)、Storage `board-media` の該当ファイル。

詳細設計(FK制約の確認、既存ミドルウェアの拡張方法等)は `/speckit-plan` で具体化する。

- [Clarified: 2026-09-10 prd-refine] メンバープロフィール閲覧(段級位・自己紹介・所属道場、既存との差分4)。今回のイテレーションでは対象外。
- [Clarified: 2026-09-10 prd-refine] OAuth(Google/Apple)ログイン(既存との差分7)。今回のイテレーションでは対象外。

## 未決事項

- [Clarified: 2026-09-10 prd-refine] 今回のイテレーションで実装するスコープは**「メンバーのロール変更」+「ボード削除」**に確定した。理由: `docs/roadmap.md` で「実質P0」と評価される最重要ギャップ(オーナーが幹部に運営を任せられない)であり、任命〜終了までの運営ライフサイクルを一貫してカバーできるため。
- [Clarified: 2026-09-10 prd-refine] メンバーのロール変更は **member⇄adminの昇降格のみ**(owner譲渡・owner降格は対象外、別タスク)。**実行権限はowner/admin両方**(adminも他のmemberをadminに昇格できる)。
- [Clarified: 2026-09-10 prd-refine] ボード削除は **物理削除(CASCADE)+ Storage(board-media)の添付ファイルも削除**。復旧不可。**実行権限はowner限定**。誤操作防止のため、削除確認は**ボード名の入力一致**で確定する(GitHub方式)。削除前にメンバー数・投稿数等の集計を表示する。
- [Clarified: 2026-09-10 prd-refine] 公開ページの見学申込フォーム、メンバープロフィール閲覧、OAuthログインは**今回のスコープ外**(下記「スコープ外」節に移動)。

## 既存との差分

`docs/aikiboard-product-overview.md` に製品として明記されているが、`docs/ARCHITECTURE.md` / `specs/{feature}/spec.md` の調査(2026-09-07時点)によれば未実装、または記述が古いもの:

1. **メンバーのロール変更(昇格・降格)は未実装**。製品概要3.4「アドミン権限を持つ幹部や事務局メンバーに、オーナー代理で管理操作を任せる運用ができます」と明記されているが、`specs/members/spec.md`によれば「ロール管理機能(昇格/降格)は実質未実装」(該当API/UIが一切見つからない)。オーナー1人が退場すると運営を引き継ぐ手段が無い。
2. **ボード削除は未実装**。製品概要10章FAQ「オーナーの方は、ボード自体を削除することでAikiBoardの利用を終了できます」と明記されているが、`specs/boards/spec.md`によれば削除APIが存在しない。
3. **公開ページの見学申込フォームは未実装**。製品概要5章「問い合わせフォーム/見学申し込み導線を設置」と明記されているが、`specs/public/spec.md`によれば「見学申し込みフォームの実装計画・仕様はコードから確認できない。マイグレーションのコメントのみに存在する未実装機能」。
4. **メンバープロフィール閲覧(段級位・自己紹介・所属道場)は未実装または不十分**。製品概要4.4「メンバー一覧から...段級位・自己紹介・所属道場が閲覧できます」と明記されているが、`specs/members/spec.md`にはこの機能への言及が無く、`docs/roadmap.md` R7バックログに「メンバープロフィール表示の拡充(概要4.4)。データはAikiNote側`public."User"`にあり、表示の充実のみ」として未着手扱い。
5. **無料トライアル期間の記述に不一致がある**。製品概要7章「30日間の無料トライアル」とあるが、`docs/roadmap.md`(R6-0、2026-07-04確定)では「60日・カード不要」に変更が確定している。製品概要の記述が古い可能性がある。
6. **メンバー人数上限の記述に不一致がある**。製品概要7章「Mini ≤20名(仮)」とあるが、`docs/roadmap.md`(R6-2、2026-07-04確定)では「Mini 15名まで」に変更が確定している。
7. **OAuth(Google/Apple)ログインは未実装**。製品概要9章「Apple ID/Googleアカウント/メールアドレスで安全にログインできます」と明記されているが、`specs/auth/spec.md`によれば実装はメール/パスワードのみ。
8. **PWA対応は未実装**。製品概要8章に記載があるが、`docs/roadmap.md`(R4-4)ではまだ未着手。
